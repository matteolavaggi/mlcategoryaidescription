# Version 1.6.0 - Google Translate Integration

## Release Goal

Dramatically reduce API costs and processing time for multi-language stores by generating content in one primary language via OpenAI, then translating to other languages using Google Translate API.

---

## Problem Statement

**Current behavior (v1.5.0):**
- For a store with 5 languages and 4 fields (description, meta_title, meta_description, link_rewrite)
- Each category requires: 5 languages × 4 fields = **20 OpenAI API calls**
- OpenAI calls are slow (~1-9 seconds each) and expensive

**Proposed behavior (v1.6.0):**
- Generate 4 fields in primary language = **4 OpenAI API calls**
- Translate to 4 other languages = **16 Google Translate API calls** (much faster & cheaper)
- Result: Same output, ~80% reduction in OpenAI costs, faster processing

### Phase 2: Google Translate Client Class

#### 2.1 Create `classes/MlCategoryAiTranslator.php`

```php
class MlCategoryAiTranslator
{
    private $apiKey;
    private $endpoint = 'https://translation.googleapis.com/language/translate/v2';
    
    /**
     * Translate text to target language
     *
     * @param string $text Source text
     * @param string $sourceLang ISO code (e.g., 'en')
     * @param string $targetLang ISO code (e.g., 'it')
     *
     * @return string|false Translated text or false on error
     */
    public function translate($text, $sourceLang, $targetLang);
    
    /**
     * Batch translate multiple texts (more efficient)
     *
     * @param array $texts Array of strings
     * @param string $sourceLang
     * @param string $targetLang
     *
     * @return array Translated texts
     */
    public function translateBatch($texts, $sourceLang, $targetLang);
    
    /**
     * Validate API key with test request
     *
     * @return bool
     */
    public function validateApiKey();
}
```

## Design Decisions (Resolved)

### 1. link_rewrite Handling
**Decision**: Generate from translated `meta_title` using PrestaShop's native `Tools::str2url()` function.

```php
// Do NOT call Google Translate for link_rewrite
// Generate locally from translated meta_title
$translatedTitle = $translatedContent[Mlcategoryaidescription::FIELD_META_TITLE] 
    ?: $category->name[$targetLangId];
$linkRewrite = Tools::str2url($translatedTitle);
```

**Rationale**:
- `Tools::str2url()` is PrestaShop's native slug generator
- Handles all special characters, accents, and edge cases
- Respects shop's `PS_ALLOW_ACCENTED_CHARS_URL` setting
- No extra API call needed - pure string processing
- Consistent with how PrestaShop core generates slugs

**Impact on flow**:
- Skip Google Translate API call for `link_rewrite` field
- Generate it locally after `meta_title` is translated
- Requires `meta_title` to be processed before `link_rewrite` (see Issue #4)

### 2. HTML Preservation in Descriptions
**Decision**: Always use `format: html` for description field translations.

```php
// For description field
$response = $this->callApi([
    'q' => $descriptionHtml,
    'source' => $sourceLang,
    'target' => $targetLang,
    'format' => 'html',  // Preserves <p>, <ul>, <strong>, etc.
    'key' => $this->apiKey,
]);
```

**Rationale**:
- Descriptions often contain HTML formatting from OpenAI
- Google Translate's `format: html` preserves tag structure
- Plain text format would strip or corrupt HTML tags

### 3. Error Handling Strategy
**Decision**: Log errors and continue, don't fallback to OpenAI.

```php
try {
    $translated = $translator->translate($text, $source, $target);
} catch (Exception $e) {
    MlCategoryAiLogger::error('Google Translate failed: ' . $e->getMessage(), [
        'category_id' => $categoryId,
        'field' => $fieldType,
        'source_lang' => $source,
        'target_lang' => $target,
    ]);
    // Skip this language, continue with others
    $failedTranslations++;
    continue;
}
```

**Rationale**:
- Fallback to OpenAI would be slow and defeat the purpose
- User can re-run failed items later
- Errors are logged with full context for debugging
- Job continues processing other languages/categories

### 4. Rate Limiting
**Decision**: Implement basic throttling for large batches.

- Google Translate limit: 600,000 characters/minute
- Average field: ~500 characters
- Safe batch: ~1,000 translations/minute
- Add configurable delay between batches if needed

## 🔍 Critical Review: Potential Issues Found

### Issue 1: Language ISO Code Mapping

**Problem**: PrestaShop uses 2-letter ISO codes, but some don't match Google Translate's expected codes.

| PrestaShop | Google Translate | Notes |
|------------|------------------|-------|
| `en` | `en` | ✅ Match |
| `fr` | `fr` | ✅ Match |
| `de` | `de` | ✅ Match |
| `it` | `it` | ✅ Match |
| `es` | `es` | ✅ Match |
| `gb` | `en` | ⚠️ British English stored as `gb` in some PS installs |
| `br` | `pt` | ⚠️ Brazilian Portuguese |
| `mx` | `es` | ⚠️ Mexican Spanish |

**Solution**: Add ISO code mapping in `MlCategoryAiTranslator`:

```php
protected static $isoCodeMap = [
    'gb' => 'en',  // British English
    'br' => 'pt',  // Brazilian Portuguese  
    'mx' => 'es',  // Mexican Spanish
    'qc' => 'fr',  // Quebec French
];

public function mapIsoCode($psIsoCode)
{
    return self::$isoCodeMap[$psIsoCode] ?? $psIsoCode;
}
```

### Issue 2: link_rewrite Must Use PrestaShop Native Function

**Requirement**: `link_rewrite` field must be a valid PrestaShop URL slug.

**PrestaShop's native methods** (from `classes/Tools.php`):
- `Tools::link_rewrite($str)` → wrapper that calls `Tools::str2url()`
- `Tools::str2url($str)` → the actual implementation

Both are equivalent. `str2url()` does:
- Converts to lowercase (using `mb_strtolower`)
- Removes/replaces accented characters (unless `PS_ALLOW_ACCENTED_CHARS_URL` is enabled)
- Replaces spaces and special chars with hyphens
- Removes invalid URL characters

**Current module code** (MlCategoryAiGenerator.php line 458):
```php
if ($fieldType === Mlcategoryaidescription::FIELD_LINK_REWRITE) {
    $content = Tools::str2url($content);
}
```
✅ This is correct and consistent with PrestaShop.

**For Google Translate flow**:
```php
// Do NOT call Google Translate API for link_rewrite
// Generate locally from translated meta_title using PS native function
if ($fieldType === Mlcategoryaidescription::FIELD_LINK_REWRITE) {
    $translatedTitle = $translatedContent[Mlcategoryaidescription::FIELD_META_TITLE];
    $content = Tools::str2url($translatedTitle);  // PS native, handles all edge cases
} else {
    $content = $translator->translate($primaryContent, $source, $target);
}
```

**Why this is safe**:
- `Tools::str2url()` handles ALL languages correctly (Chinese, Arabic, Cyrillic, etc.)
- Respects shop's `PS_ALLOW_ACCENTED_CHARS_URL` setting
- Same function used by PrestaShop core for all slugs
- No risk of invalid characters in URL

### Issue 3: link_rewrite Source Text

**Question**: What text should we use to generate the translated `link_rewrite`?

**Options analyzed**:
| Source | Pros | Cons |
|--------|------|------|
| Category `name` | Always exists | Often too short/generic |
| `meta_title` | SEO-optimized, descriptive | Must be translated first |
| OpenAI-generated slug | Current behavior | Extra API call, defeats GT purpose |

**Decision**: Use translated `meta_title` → `Tools::str2url()`

**Rationale**:
- `meta_title` is already SEO-optimized (that's its purpose)
- No additional API call needed (Google Translate or OpenAI)
- Consistent with how many CMS systems generate slugs
- Falls back to category name if meta_title is empty

**Implementation** (see Issue 2 for full code):
```php
// link_rewrite is NOT translated via API
// It's generated from the translated meta_title using PS native function
$translatedTitle = $translatedContent[Mlcategoryaidescription::FIELD_META_TITLE] 
    ?: $category->name[$targetLangId];  // Fallback to category name
$linkRewrite = Tools::str2url($translatedTitle);
```

### Issue 4: Processing Order Dependency

**Problem**: If we generate `link_rewrite` from `meta_title`, we must ensure `meta_title` is translated first.

**Current flow** (buildItemsList in MlCategoryAiJobQueue.php):
```php
foreach ($job['fields_to_generate'] as $fieldType) {
    $items[] = [...];
}
```

Fields come from job config, order not guaranteed.

**Solution**: Enforce field order when GT is enabled:

```php
$fieldOrder = [
    Mlcategoryaidescription::FIELD_DESCRIPTION,
    Mlcategoryaidescription::FIELD_META_TITLE,      // Must be before link_rewrite
    Mlcategoryaidescription::FIELD_META_DESCRIPTION,
    Mlcategoryaidescription::FIELD_META_KEYWORDS,
    Mlcategoryaidescription::FIELD_LINK_REWRITE,    // Last, depends on meta_title
];

// Sort fields_to_generate by this order
$sortedFields = array_intersect($fieldOrder, $job['fields_to_generate']);
```

### Issue 5: Batch Translation Efficiency - REVISED ARCHITECTURE

**Problem**: Current architecture processes items one-by-one in a flat list. With Google Translate mode, we need a two-phase approach.

**Current `buildItemsList()` output** (from MlCategoryAiJobQueue.php):
```
[
  {id_category: 1, id_lang: 1 (EN), field_type: description},
  {id_category: 1, id_lang: 1 (EN), field_type: meta_title},
  {id_category: 1, id_lang: 2 (IT), field_type: description},  ← Can't translate yet!
  {id_category: 1, id_lang: 2 (IT), field_type: meta_title},
  ...
]
```

Items are interleaved - can't batch translate because we need ALL primary language content first.

---

**PROPOSED SOLUTION: Two-Phase Job Processing**

When Google Translate is enabled, modify the job flow:

```
┌─────────────────────────────────────────────────────────────┐
│ PHASE 1: OpenAI Generation (Primary Language Only)          │
├─────────────────────────────────────────────────────────────┤
│ Process ALL fields for ALL categories in primary language   │
│                                                             │
│ Cat 1 → EN → description ──────────┐                        │
│ Cat 1 → EN → meta_title ───────────┼──► OpenAI API          │
│ Cat 1 → EN → meta_description ─────┤                        │
│ Cat 2 → EN → description ──────────┤                        │
│ Cat 2 → EN → meta_title ───────────┘                        │
│ ...                                                         │
│                                                             │
│ Result: Primary content saved to DB + cached in memory      │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ PHASE 2: Google Translate (All Target Languages)            │
├─────────────────────────────────────────────────────────────┤
│ For each target language, batch translate ALL content       │
│                                                             │
│ Target: Italian ──────────────────────────────────────────  │
│   Batch translate: [desc1, title1, meta1, desc2, title2...] │
│   Generate link_rewrite from translated meta_title          │
│   Save all to DB                                            │
│                                                             │
│ Target: French ───────────────────────────────────────────  │
│   Batch translate: [desc1, title1, meta1, desc2, title2...] │
│   Generate link_rewrite from translated meta_title          │
│   Save all to DB                                            │
│ ...                                                         │
└─────────────────────────────────────────────────────────────┘
```

**Modified `processNextBatch()` flow**:

```php
public function processNextBatch($idJob, $module, $batchSize = 5)
{
    $job = $this->getJob($idJob);
    
    if ($job['use_google_translate']) {
        if ($job['phase'] === 'openai') {
            // Phase 1: Process primary language with OpenAI
            $result = $this->processOpenAiPhase($job, $module, $batchSize);
            
            if ($result['phase_complete']) {
                // Move to translation phase
                $this->updateJob($idJob, ['phase' => 'translate']);
            }
        } else {
            // Phase 2: Translate to other languages
            $result = $this->processTranslatePhase($job, $module, $batchSize);
            
            if ($result['phase_complete']) {
                $this->updateJob($idJob, ['phase' => 'completed']);
            }
        }
    } else {
        // Original flow (no GT)
        $result = $this->processOriginalFlow($job, $module, $batchSize);
    }
    
    return $result;
}
```

**New method: `processTranslatePhase()`**:

```php
protected function processTranslatePhase($job, $module, $batchSize)
{
    $translator = new MlCategoryAiTranslator($module->getGoogleApiKey());
    $primaryLangId = $job['primary_language_id'];
    $primaryLangIso = Language::getIsoById($primaryLangId);
    $translateLangIds = json_decode($job['translate_language_ids'], true);
    
    // Build items for current batch
    // Structure: process one target language at a time, batch all categories
    $currentTargetLang = $translateLangIds[$job['current_translate_lang_index'] ?? 0];
    $targetLangIso = Language::getIsoById($currentTargetLang);
    
    // Get all primary content for batch of categories
    $categoryBatch = array_slice($job['category_ids'], $job['current_translate_position'], $batchSize);
    
    $textsToTranslate = [];
    $textMapping = [];  // Track which text belongs to which category/field
    
    foreach ($categoryBatch as $idCategory) {
        foreach ($job['fields_to_generate'] as $fieldType) {
            // Skip link_rewrite - generated locally
            if ($fieldType === Mlcategoryaidescription::FIELD_LINK_REWRITE) {
                continue;
            }
            
            $primaryContent = $this->getPrimaryContent($idCategory, $primaryLangId, $fieldType);
            
            if (empty(trim($primaryContent))) {
                MlCategoryAiLogger::warning('Skipping translation: primary content empty', [
                    'category_id' => $idCategory,
                    'field' => $fieldType,
                ]);
                continue;
            }
            
            $textsToTranslate[] = $primaryContent;
            $textMapping[] = [
                'id_category' => $idCategory,
                'field_type' => $fieldType,
            ];
        }
    }
    
    // Batch translate all texts at once
    $format = 'text';  // Will be overridden per-field below
    $translations = $translator->translateBatch($textsToTranslate, $primaryLangIso, $targetLangIso);
    
    // Save translated content
    foreach ($translations as $index => $translatedText) {
        $mapping = $textMapping[$index];
        $category = new Category($mapping['id_category'], $currentTargetLang);
        
        $generator = new MlCategoryAiGenerator($module);
        $generator->updateCategoryFieldPublic($category, $mapping['field_type'], $translatedText, $currentTargetLang);
    }
    
    // Generate link_rewrite from translated meta_title
    foreach ($categoryBatch as $idCategory) {
        if (in_array(Mlcategoryaidescription::FIELD_LINK_REWRITE, $job['fields_to_generate'])) {
            $category = new Category($idCategory, $currentTargetLang);
            $translatedTitle = $category->meta_title ?: $category->name;
            $linkRewrite = Tools::str2url($translatedTitle);
            
            $generator->updateCategoryFieldPublic($category, Mlcategoryaidescription::FIELD_LINK_REWRITE, $linkRewrite, $currentTargetLang);
        }
    }
    
    return [...];
}
```

### Issue 6: HTML Format for Non-Description Fields

**Problem**: Plan says use `format: html` for descriptions, but what about other fields?

**Analysis**:
- `description`: HTML content ✅ use `format: html`
- `meta_title`: Plain text, may have HTML entities like `&amp;`
- `meta_description`: Plain text
- `meta_keywords`: Comma-separated text
- `link_rewrite`: Generated locally, no API call

**Solution**: Use `format: html` only for description, `format: text` for others:

```php
$format = ($fieldType === Mlcategoryaidescription::FIELD_DESCRIPTION) ? 'html' : 'text';
```

### Issue 7: Empty Primary Content Handling

**Scenario**: OpenAI was called but returned empty content (API error, content filtered, etc.)

**Note**: If OpenAI returns a valid response, content should NOT be empty. Empty content indicates an upstream issue that was already logged during the OpenAI phase.

**Behavior**: Skip translation for that field and log a warning:

```php
foreach ($fieldsToTranslate as $fieldType) {
    $primaryText = $primaryContent[$fieldType] ?? '';
    
    if (empty(trim($primaryText))) {
        MlCategoryAiLogger::warning('Skipping translation: primary content is empty', [
            'category_id' => $idCategory,
            'field' => $fieldType,
            'primary_lang' => $primaryLangIso,
            'target_lang' => $targetLangIso,
            'reason' => 'OpenAI generation may have failed for this field',
        ]);
        $skippedTranslations++;
        continue;
    }
    
    // Proceed with translation
    $translated = $translator->translate($primaryText, $primaryLangIso, $targetLangIso);
}
```

**Log output example**:
```
[WARNING] Skipping translation: primary content is empty - category_id=42, field=description, primary_lang=en, target_lang=it
```

**Why warning (not error)**:
- The actual error occurred in the OpenAI phase (already logged there)
- This is a downstream consequence, not a new error
- Job should continue processing other fields/categories
